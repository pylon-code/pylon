# Glossary

Terms whose meaning matters across Pylon. Architecture and lifecycle constraints belong in the
[overview](./overview.md), not in these definitions.

## Workspace and conversation

| Term           | Meaning                                                                                                                                                                                      |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Environment    | One running server and the machine, credentials, workspace access, and state it owns.                                                                                                        |
| Client         | A web, desktop, or mobile UI connected to an environment. The desktop app can also host a server.                                                                                            |
| Project        | An environment-local workspace record rooted at a directory.                                                                                                                                 |
| Workspace root | The project's base filesystem directory on the environment.                                                                                                                                  |
| Worktree       | A separate Git checkout a thread can use instead of the project's main checkout.                                                                                                             |
| Thread         | The durable conversation and work history for a project. It survives provider process exits.                                                                                                 |
| Turn           | One user-to-agent work cycle. Provider work can finish before checkpoint and diff work settles.                                                                                              |
| Turn window    | A bounded page of a thread's turns that carry a user message, with subagent and fan-out turns kept beside their anchor. Requests opt in, gated on the `threadSnapshotPagination` capability. |
| Activity       | A non-message timeline item, such as a tool action, approval, or failure.                                                                                                                    |
| Thread plan    | The ordered steps an agent reports for a turn, projected as thread state from the provider's own plan or todo output. Each step is `pending`, `inProgress`, or `completed`.                  |
| SnapShot       | A desktop capture of another app's window, attached to a composer draft as an image carrying its app name, window title, icon, and optional accessibility data.                              |
| Runtime home   | The base data directory, `~/.pylon-code` by default. Runtime state normally lives under its `userdata` directory.                                                                            |

## Orchestration

| Term                    | Meaning                                                                                      |
| ----------------------- | -------------------------------------------------------------------------------------------- |
| Command                 | A request to change domain state. Accepting it does not mean its side effects have finished. |
| Event                   | A persisted fact produced by a command.                                                      |
| Decider                 | The pure logic that turns a command and current state into events.                           |
| Projection / read model | A view of current state derived from persisted events.                                       |
| Projector               | The logic that applies events to a read model.                                               |
| Reactor                 | A worker that performs follow-up work in response to recorded intent or runtime signals.     |
| Command receipt         | A durable record of a command's result, used to make retries idempotent.                     |
| Runtime receipt         | A test-only signal that an asynchronous milestone completed.                                 |
| Quiesced                | The relevant follow-up workers have finished, beyond the provider turn merely ending.        |

## Providers and checkpoints

| Term                     | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Provider                 | The agent runtime Pylon controls, such as Codex, Claude Code, or Prime Agent.                                                                                                                                                                                                                                                                                                                                                                                    |
| Driver                   | The integration for a provider kind.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Provider instance        | One configured provider, with its own settings and lifecycle. Multiple instances can use the same driver.                                                                                                                                                                                                                                                                                                                                                        |
| Adapter                  | The boundary translating a provider's native protocol into Pylon operations and events.                                                                                                                                                                                                                                                                                                                                                                          |
| Session                  | The provider runtime attached to a thread. A session can be stopped and resumed without deleting the thread.                                                                                                                                                                                                                                                                                                                                                     |
| Managed provider build   | A signed provider CLI build installed side by side in an environment's runtime home and selected for one provider instance, without replacing the user's own installation. Prime Agent is the first provider with this lifecycle. See [managed installation](./prime-agent-managed-install.md).                                                                                                                                                                  |
| Pylon Prime build        | A Prime Agent build whose loaded SDK and daemon handshake prove the capabilities native sessions need, including session isolation, cleanup, transcript snapshots, and event continuity. A fork name or version alone does not establish compatibility. A compatible manual install enables native mode; Pylon-managed distribution adds the provenance managed lifecycle and restart recovery require. See the [parity ledger](./prime-agent-daemon-parity.md). |
| ACP compatibility mode   | Pylon's reduced fallback connection to Prime Agent over the Agent Client Protocol when the installation or launch arguments cannot use the native daemon. See the [mode comparison](../user/providers-prime-agent.md#configure-pylon).                                                                                                                                                                                                                           |
| Runtime mode             | The thread's permission policy. See [permission modes](../user/permission-modes.md).                                                                                                                                                                                                                                                                                                                                                                             |
| Interaction mode         | How the agent approaches the task, such as planning. Separate from permission policy.                                                                                                                                                                                                                                                                                                                                                                            |
| Checkpoint               | A saved workspace state used for diffs and restore, stored as a hidden Git ref.                                                                                                                                                                                                                                                                                                                                                                                  |
| Checkpoint baseline      | The workspace state captured before the work being compared.                                                                                                                                                                                                                                                                                                                                                                                                     |
| Turn diff                | The workspace changes attributed to one turn.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Rollback saga            | A durable server-owned operation that moves a checkpoint-managed workspace and an exact provider conversation anchor to the same earlier turn, committing `thread.reverted` last or compensating to the source. See [exact conversation rollback](./rollback-recovery.md).                                                                                                                                                                                       |
| Workspace rollback lease | The durable fence on one Git workspace while a rollback saga is active. It blocks turns, provider input and queue changes, checkpoint and Git mutations, and session stops from every thread sharing that workspace.                                                                                                                                                                                                                                             |
| Manual recovery          | The rollback state kept when Pylon cannot prove both the workspace and the conversation are at the target or the restored source. The lease stays active, and clients see only a redacted reason and the recovery actions the saga permits.                                                                                                                                                                                                                      |
